Implementa las capas back y front de la spec `specs/<spec>.spec.md`.

- Piensa antes de programar: lee el contexto, haz tus supuestos y, en caso de duda, hazme una pregunta cerrada.
- Simplicidad primero: el mínimo código que cumple la spec. Nada especulativo.
- Cambios quirúrgicos: toca solo lo necesario y sigue el estilo del código existente.
- Orientado a objetivos: cada criterio EARS es un objetivo verificable.

- Tests unitarios solo de la capa de servicio (lógica), con datos fake.
- No hagas tests de la capa de entrada (rutas, controladores, componentes) ni de infraestructura (persistencia, HTTP).

- Termina cuando `vp check` y `npm test` pasen.
