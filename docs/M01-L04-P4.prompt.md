Implementa las pruebas e2e con Playwright a partir de los ficheros `specs/<spec-id>-*.feature`.

- Piensa antes de programar: lee el contexto, haz tus supuestos y, en caso de duda, hazme una pregunta cerrada.
- Simplicidad primero: el mínimo código que cumple la spec. Nada especulativo.
- Cambios quirúrgicos: toca solo lo necesario y sigue el estilo del código existente.
- Orientado a objetivos: cada criterio EARS es un objetivo verificable.

- Un spec por feature en `e2e/tests/<name>.spec.ts`. Feature en `test.describe()`, escenario en `test()`.
- Pasos `// GIVEN`, `// WHEN`, `// THEN` en comentarios.
- `Background` en `test.beforeEach()`. `Scenario Outline` en un bucle sobre `Examples`.
- Datos previos en `e2e/core/seed-data.ts`; el resto, únicos con `Date.now()`.
- Localiza por rol y nombre accesible.
- No hagas tests unitarios del codigo de pruebas e2e.

- Termina cuando `npm run typecheck` y `npm test` en `e2e/` pasen.
